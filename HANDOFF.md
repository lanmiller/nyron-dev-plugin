# Хендофф: состояние работ по плагину и STOVP

Точка входа для новой сессии. Обновлено: 01.08.2026.
Читать в этом порядке: [VISION.md](VISION.md) — зачем и куда;
[SYSTEM-MAP.md](SYSTEM-MAP.md) — 25 функций «сейчас → будет»;
этот файл — что уже сделано и что делать дальше.

**Рамка сессии**: работаем над плагином и системой STOVP. Продуктовые дефекты
проектов (evolve, psylia и прочие) в этой работе не разбираем — для них свои
эпики и волны.

## Что решено (кратко; обоснования — в VISION)

1. **Строим STOVP** — оркестратор фабрики: демон `stovpd` (Python/FastAPI),
   веб-морда Stovp (SvelteKit) + Telegram Mini App, CLI. Плагин nyron-dev
   остаётся боевым всю стройку; big-bang запрещён.
2. **Job-модель** — единица исполнения: взял задание → шаг → чекпойнт →
   завершился. Вотчеры и пробуждения уходят как класс.
3. **Порядок дорожной карты**: 0 гигиена → **2 UJM и каноны** → 1 сигнал
   (алерты, бэкап, безопасность) → 3 демон → 4а/4б флот → 5 продуктовая
   петля. UJM переехал вперёд: каталог путей — линейка серьёзности для всей
   фабрики и формат передачи работы QA.
4. **Триаж находок тремя корзинами** (в канон волн): ломает путь из
   каталога → дефект; поведения в каталоге нет → вопрос замысла
   постановщику; не ломает → перечень долга. Плюс потолок кругов ревью
   (2, для сложного 3) — дальше решение человека, а не следующий круг.
5. **Стандарт задачи усилен**: обязательное поле «путь UJM / шаг»,
   «Как тестировать» разделено на «Приёмка руками» и «Проверки
   разработчика», гейт статуса (нет приёмки — нет перехода в тестирование).
6. **Документация тремя слоями**: репо/vault — истина, Confluence — витрина
   (рендер md2conf), внешний тест-менеджмент — проекция каталога UJM.
7. **Секреты — три хранилища по потребителю**: переменные CI проекта/группы
   для пайплайнов, локальный стор машины для демона и ботов, ssh-config для
   подключений. В документах — имена, не значения.
8. **Пакеты плагина по ролям** (потом, этап 2): core / product / qa /
   dispatch; роль = пакет, проект = конфиг.
