# Ресёрч-дайджест к VISION (27.07.2026)

Пять независимых прогонов: Terra (gpt-5.6-terra, архитектурный челлендж по
знаниям) + 4 веб-ресёрчера (флот, observability, QA-стек, QA-модели).
Полные тексты — в транскриптах сессии; здесь выжимка и синтез.

## Консенсус всех источников

1. **Будка SQLite — правильная архитектура.** Индустрия сошлась на «локальный
   SQLite+WAL под MCP» (MCP Agent Mail 2k★, Claude Peers, Mission Control).
   Готовой замены триплету «сообщения + брони + очередь мержа» нет. Но ядро
   надо усилить: транзакционные lease, outbox, идемпотентность (Terra),
   FTS5-поиск и git-markdown-аудит (паттерн Agent Mail).

2. **«Будить спящие сессии» — тупиковая ветка.** Официально признанная дыра
   Claude Code (issues #44380, #27441, #28229); tmux send-keys — антипаттерн
   (~70–80% надёжности). Единственный 100%-механизм — stdin stream-json у
   процессов под Agent SDK / `claude -p`. Правильная модель исполнения —
   конечные job-процессы: lease → шаг → checkpoint → exit (Terra п.3).
   Следствие: демон-«будильщик» Desktop-сессий — временный мост, не строить
   его богатым.

3. **Parallels выкидывается.** Консенсус-механика мультиаккаунта:
   `CLAUDE_CONFIG_DIR=~/.claude-accN` на профиль (задокументировано у Maestro:
   раздельные auth/квоты/история, общие настройки симлинками). ToS: свои
   несколько Max-аккаунтов — ок; канонично-безопасный путь — дирижёр порождает
   ОФИЦИАЛЬНЫЙ CLI/SDK как subprocess, OAuth-токены не извлекать. Риск:
   fingerprint-баны (одна машина/IP/платёжка) — разные плательщики, не
   молотить аккаунты синхронно одинаковой нагрузкой.

4. **Готового дирижёра нет — строим свой тонкий, крадём паттерны.**
   - Claudexor (317★, MIT) — прямое попадание в спеку (мультиаккаунт, ротация
     по typed vendor-limit сигналам, 429-парковка, headless-резюм, daemon с
     очередью) — донор архитектуры, не фундамент (bus-factor 1).
   - gastown (17k★) — оркестрация/merge-queue/health, но без мультиаккаунта,
     тяжёлый и opinionated. vibe-kanban — sunsetting; Crystal — deprecated.
   - claude_code_agent_farm — референс supervision (heartbeat, auto-restart,
     backoff). ccusage (17.5k★) — сенсор лимитов (JSON, 5-час блоки, live).
   - claude-auto-resume — паттерн детекта limit-сигнала и планового резюма
     (нативного авторезюма в CLI нет, issues открыты).

5. **QA-стек собирается из готовых зрелых частей, писать почти нечего:**
   - Каталог сценариев: **playwright-bdd** (vitalets) — `.feature` = человеко-
     и ИИ-читаемый каталог (владелец — QA-человек), степы/фикстуры — код,
     нативный Playwright-раннер, теги `@predprod @smoke @multiuser`.
   - Генерация/починка: **официальные Playwright Test Agents** (v1.56+,
     Planner/Generator/Healer, `--loop=claude`) — Healer = наш сценарий
     «дешёвая модель чинит упавшее», и чинит В ВЕТКУ/MR, не в канон
     (совпадает с Terra п.13: QA-модель предлагает PR, baseline не трогает).
   - Мультиюзер/CRDT: фикстура на 2–3 contexts + рецепт Liveblocks
     (уникальный board на тест, poll-ассёрты сходимости). ~50 строк, либ нет.
   - Ночная регрессия: launchd → `playwright test --grep @regression` →
     **playwright-reports-server** (self-hosted, флаки-скоринг, тренды) +
     шаг headless-healer. Хрупкие места: Stagehand act() с кэшем действий.
   - Не брать: Healenium (Selenium-центричен), Skyvern/browser-use (не наш
     слой), Gherkin-полный Cucumber (playwright-bdd достаточно).

6. **QA-модель: фаворит GLM Coding Plan Pro (~$30/мес).** Единственный
   закрывает все критерии: дешёвая флэт-подписка, каноничная совместимость с
   Claude Code (нулевая миграция тулинга), vision-путь (Vision-MCP +
   GLM-5V-Turbo), верх открытой лиги по коду. Риск: квота в промптах, не
   токенах (агентная сессия жжёт быстро) — пилот сразу на Pro. Запасной:
   Kimi Code $19 (лучший нативный vision у K2.7, но подписки K3
   приостановлены 20.07, квоты непрозрачны). Отсеяны: MiniMax (vision через
   API не работает — issue #92), Qwen (халявы нет с апреля), DeepSeek (нет
   подписки/vision/CLI), локальный запуск (только текст-fallback, 64+ ГБ).

7. **Наблюдаемость не изобретать:** нативная OTel-телеметрия Claude Code
   (токены/стоимость/api_error, prometheus :9464 без коллектора, включается
   env-переменными на весь флот) + ccusage поверх JSONL; готовые Grafana-
   дашборды (25052) как опция. Свой — только тонкий веб над нашей же SQLite
   (read-only WAL, SSE по fswatch). Mission Control (5.9k★, alpha) — план Б.
   Алерты: Telegram Bot API однострочник из хуков Notification/Stop +
   heartbeat-чекер; CCGram — одобрение permissions с телефона.

8. **Мерж: источник истины — Git-платформа** (у нас GitLab: MR checks,
   protected branches, merge trains), самодельная очередь — только локальные
   брони worktree (Terra п.9).

## Стратегические риски (новые, в VISION их не было)

- **Разморозка «Agent SDK credit»**: перевод headless/SDK на отдельный кредит
  по API-ценам анонсировался на 15.06.2026 и ОФИЦИАЛЬНО ПРИОСТАНОВЛЕН.
  Если разморозят — экономика фермы подписок ломается (~$100–200/мес кредита
  на аккаунт). Дирижёр обязан уметь fallback: API-ключи или интерактивный
  режим. Это риск №1 всей стройки «флот».
- **Fingerprint-баны мультиаккаунта**: известны баны легитимных
  мультиаккаунтщиков; митигции — п. «Консенсус-3».
- **Entitlement до техники** (Terra п.14): «подписка = программная ёмкость»
  не доказано; подтвердить допустимость сценария до этапа «флот».

## Предлагаемые правки VISION (к шторму)

1. Этапы «Демон» и «Флот» пересобрать вокруг job-модели: воркер = конечный
   процесс с lease/checkpoint; wake-протокол для Desktop-сессий — только
   временный мост, не инвестировать.
2. Схему будки усилить: jobs/attempts/leases/events(outbox), idempotency,
   FTS5, git-аудит сообщений.
3. Дорожную карту сузить в вертикаль (Terra п.18): после гигиены — один
   проект, один CLI-профиль, один тип задачи, один сценарий; расширение ролей
   и проектов — после надёжного цикла.
4. KPI этапа «Флот» заменить (Terra п.19): не «эпик без клика», а «атомарная
   задача Jira → PR → CI → сценарий без ручного пинка; при сбое — точный алерт
   и воспроизводимый checkpoint».
5. Мерж-очередь: GitLab merge trains — источник истины; будка — только брони.
6. QA-раздел: зафиксировать стек (playwright-bdd + Test Agents + reports-
   server + мультиюзер-фикстуры) и правило «QA-модель чинит в MR, не в канон».
7. Выбор QA-модели: пилот GLM Pro неделю (4 проверочных сценария из ресёрча),
   Kimi trial параллельно только на vision-сравнение.
8. Риски: добавить разморозку SDK-кредита, fingerprint-баны, промпт-квоты GLM.
9. Полка инструментов: Claudexor/Maestro/agent_farm/ccusage/auto-resume как
   доноры паттернов; OTel+ccusage как сенсоры; Agent Mail как донор для будки.
