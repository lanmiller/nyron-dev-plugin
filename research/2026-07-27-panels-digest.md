# Дайджест ролевых панелей (27.07.2026, ночь)

Пять источников: Sol (28 пунктов, имплементируемость/эксплуатация),
продуктовая панель (методолог+аналитик+биздев, 16), инженерная панель
(тимлид+фулстек+SRE, 22), панель качества и людей (QA+онбординг+безопасник,
18), ресёрч ролевых скиллов (паттерны на кражу). Всего ~85 находок, после
дедупа — 6 MECE-групп. Полные тексты — в транскриптах сессии.

Вес находки = сколько независимых источников её назвали (⚡ = 3+).

## А. Измеримость и приёмка (фабрика не умеет мерить себя)

1. ⚡ Критерии этапов нефальсифицируемы: «сутки без пинков» проходится
   пустыми сутками; «ручной пинок» нигде не логируется (Sol-9, тимлид-5,
   QA-1, аналитик-1). → Событие `human_intervention` в будке с этапа 0;
   критерий 0 = «сутки при ≥N активных волнах ≥2 проектов» + fault-injection
   прогон; критерий 4а = «N тикетов подряд разных типов, ≥K% без
   вмешательств».
2. ⚡ Baseline не снят — окупаемость STOVP будет недоказуема (Sol-4,
   аналитик-2, биздев-4). → Тикет «снять baseline» в этап 0 (Jira changelog,
   ccusage, журнал вмешательств за неделю).
3. Мета-метрики фабрики отсутствуют в VISION (аналитик-3). → Топ-5: cycle
   time по стадиям; доля автономных прохождений; стоимость тикета в
   окнах+токенах (требует ticket-id в контексте job'а — заложить в
   job-модель, задним числом не восстановить); first-pass yield; утилизация
   флота/голодание.
4. Alert precision: доля алертов→действий, еженедельно; precision <50% две
   недели → сенсор перенастроить/выключить (аналитик-4, SRE-7: + severity
   и quiet hours — critical будит, routine в утренний дайджест).
5. Synthetic-canary мониторинга: периодический намеренный сбой обязан
   рождать алерт; тишина = алерт (QA-4). Композитный тест «усыпить Мак на
   30 мин при активной волне» → один сводный алерт, не 15 (SRE-8).
6. Стройка не подчиняется собственной дисциплине гипотез: ключевые ставки
   (job-модель, headless-экономика, Claudexor) без карточек с порогами
   (методолог-1 + Sol-4). → 3 карточки гипотез по образцу GLM-пилота.

## Б. Безопасность и границы данных (не написано ни строчки — блокер)

1. ⚡ SECURITY-канон отсутствует, а этапы 1–2 уже раздают токены и
   открывают транскрипты (безопасник-все, фулстек-2, SRE-6). → Документ на
   страницу ДО этапа 1: единый стор секретов (chmod 700 вне репо/vault или
   Keychain), env-инъекция при запуске (не в конфиги/argv/промпты), реестр
   секрет→владелец→ротация, gitleaks в CI.
2. ⚡ Вышка/транскрипты: auth обязателен даже в tailnet (пароль/basic),
   запрет Funnel, Tailscale ACL, redaction токенов в отображаемом,
   не отдавать сырой JSONL (безопасник-2, фулстек-2, QA/люди).
3. **Код проектов уходит в Zhipu (GLM)** — решение принимается молча фактом
   покупки (безопасник-3). → Политика данных per-вендор ДО пилота: GLM
   можно тестовый стенд/синтетический seed/e2e-код; нельзя прод-данные,
   секреты, чувствительную бизнес-логику (betzo-гемблинг — решить явно);
   deny-list путей в конфиге QA/рефакторинг-ролей; рефакторинг-контур на
   GLM пересмотреть (объём кода максимален).
4. Telegram: алерт = тип события + ссылка на вышку, payload не пересылать;
   chat_id-проверка (безопасник-4).
5. Публичный разрез stovp: только свежий репо без истории, ноль проектных
   фактов в ядре, приватный оверлей для команды, gitleaks+ручной аудит до
   первого push (безопасник-5).
6. Бэкап — чувствительный артефакт: шифрованный, с описью, restore-прогон
   ежемесячно; FileVault обязателен; runbook «ротация после инцидента»
   (SRE-5, безопасник-6).

## В. Эксплуатация платформы (ночь, когда фабрика молча стояла)

1. ⚡ Dead-man's switch вне Мака: вышка пингует внешний сервис (или наши
   серверы agents/nyron), нет пинга → алерт снаружи (SRE-4, QA-4). Тикет S.
2. ⚡ Бэкап будки/БД: hot-backup (`VACUUM INTO`/`.backup`, не cp живого
   WAL) + внешний носитель + restore-тест (SRE-5, Sol-25). В плане не было
   вовсе.
3. Сон/перезагрузка Мака: fencing-token в lease (двойник после сна),
   caffeinate-политика, автообновления macOS только ручным окном,
   решение по FileVault/автологину, runbook холодного старта (SRE-1, SRE-2).
4. Диск: retention trace/video/JSONL и алерт «диск < X ГБ» ДО включения
   ночной регрессии, не на этапе 3 (SRE-3). Ресурсные лимиты и приоритет
   боевых job (Sol-24).
5. WAL будки сегодня никто не чекпойнтит (жив факт: 4МБ WAL) — паттерн
   чтения: короткие ro-коннекты + busy_timeout, снапшот-копии; решить, кто
   чекпойнтит до демона (фулстек-1).
6. launchd-спайк ДО стройки вышки: Keychain недоступен демону (логин-токены
   CLI!), PATH, LaunchAgent vs Daemon, FileVault (фулстек-3) — результат
   меняет архитектуру вышки и демона.
7. SSE: reconnect с Last-Event-ID (iOS рвёт фон), adapter-node нюансы
   (фулстек-2). JSONL-tail: fsnotify+курсор+толерантный парсер — отдельный
   модуль (фулстек-4). SQLite-очередь: BEGIN IMMEDIATE + fencing; решить
   «одна база или две» в контракте сейчас (фулстек-6).
8. Независимый break-glass: диагностика/рестарт/restore без STOVP (Sol-25).
9. Реестр внешних зависимостей с ценой форка на вышке (биздев-6, Sol-26):
   версии зафиксировать, окно обновлений, smoke после апдейта.

## Г. Люди и онбординг (провал на установке, до первого скилла)

1. ⚡ Установка не пройдена даже у автора; путь Агиля — стена из 5 шагов
   (онбординг-1, Sol-27). → Гайд «первый день» per-роль (30 мин,
   скриншоты), смоук «скажи X — получи Y», проверка доступов до T2-08.
2. Приёмка разбивки на пакеты = «член команды поставил сам по гайду и
   прошёл сценарий в песочнице», не «smoke на чистой машине» (онбординг,
   Sol-27).
3. Песочный Jira-проект + режим «покажи, не делай» на первую неделю роли;
   канал «у меня сломалось» с SLA; doctor с человекочитаемым выводом
   (онбординг-5,6,2).
4. Вышка этапа 1 — инструмент одного владельца (решить явно); командные
   виды с авторизацией — отдельный тикет позже (онбординг-4).
5. Марина не описана; вход Юры не пилотирован — по одному реальному
   сценарию до объявления канона (онбординг-3).
6. Jira + STATUS.md + ROADMAP.md для непрограммистов — три поверхности
   синхронизации: ручной ввод только Jira, остальное генерится (Sol-18).

## Д. Порядок и экономика стройки

1. ⚡ Bootstrap-цикл: этап 0 чинит механизм пробуждения — нельзя делать
   волнами, которые он будит (тимлид-1). → Этап 0 = синхронные сессии под
   глазами человека; волновой режим после критерия.
2. ⚡ Этап 1 в текущем виде — одноразовая стройка с худшим ROI (биздев-1,
   Sol-11, фулстек-5): адаптеры к умирающему контуру + SvelteKit-продукт.
   → Этап 1 порезать до «Сигнал»: Telegram-алерты + готовые сенсоры
   (ccusage, готовые Grafana-дашборды) + dead-man + бэкап + секрет-канон;
   полная вышка строится ОДИН раз поверх stovpd (этап 3+).
3. ⚡ T2-08 (пакеты+переименование) — максимальный радиус поражения
   (тимлид-2, Sol-7): отдельное окно после стабилизации, алиасы старых
   имён ≥2 релиза, миграция конфигов потребителей отдельным тикетом,
   nyron-dev как фасад.
4. ⚡ Календарь и мощность: конец этапа 2 реалистично 2.5–3.5 мес, 4а — к
   концу года; параллельность 1+2 ложная (последовательны по человеку);
   нужна явная квота окон на стройку (напр. одно 5-час окно одного
   аккаунта в день), иначе стройка голодает вечно (тимлид-6,7, Sol-2,
   биздев-4).
5. План пуст после этапа 2: демон/миграция живой hub.db/флот не разложены;
   миграция будки = теневой демон без права записи + backward-compatible
   схема + downgrade (Sol-1, Sol-22). Тикеты на снос переходных мостов —
   по их же легаси-политике (Sol-23, методолог-3).
6. «Fallback на API» = остановка фабрики по их же правилам: посчитать
   unit-экономику тикета до этапа 3, определить минимальный выживающий
   режим (алерты + UJM-регрессия на GLM) (биздев-2).
7. git cherry ненадёжен при squash — карантин/bundle с TTL вместо
   немедленного удаления (Sol-28). Смоук-сьют плагина — тикет этапа 0:
   hub-тесты обязательным prerelease + golden-сценарии 3–4 скиллов +
   приёмка мини-волной end-to-end (QA-2,3).
8. Достроить: seed/test-data контур стенда — отдельный тикет до T2-02
   (тимлид-3); OTel — отдельный тикет, один профиль, свой коллектор
   (фулстек-7); vendor-API квот — best-effort, приёмка не зависит
   (тимлид-4); event-канон аналитики (реестр событий) рядом с UJM,
   события аналитики в DoD фич — с этапа 2 (аналитик-5, методолог-2).

## Е. Паттерны на кражу из чужих скиллов (все фреймы — через владельца!)

1. TEMPLATE.md + EXAMPLE.md + CI-линт структуры скиллов (pm-skills, 505★).
2. «Markdown-флоу → генерируемый Playwright-spec» (neonwatty) — мост
   UJM→e2e: человекочитаемый сценарий как источник, спеки производные.
3. /compound — обязательный шаг «что выучили» после эпика в docs-репо
   (EveryInc, 23.5k★) — в nyron-waves/qa-handoff.
4. Журнал допущений + peer-review-чеклист замера (data-analytics-skills,
   325★) — в вердикт гипотезы product-flow.
5. Агент-критик артефактов (pm-critic) — расширить cross-review с кода на
   гипотезы/требования/тест-планы. Adaptive Decision Ladder и секция
   Common Pitfalls (deanpeters, 6k★ — CC BY-NC-SA: только идеи, не текст).
Не трогать: чужие фреймы/шаблоны без ручной сверки владельцем; чужие
стадийные модели; вендорские обёртки; мегасборники.

## Решения, принятые по итогам панелей (внесены в VISION)

1. Этап 0 — синхронно, с журналом вмешательств, смоук-сьютом плагина,
   baseline и fault-injection приёмкой.
2. Этап 1 переопределён: «Сигнал» (алерты-минимум + SECURITY-канон +
   dead-man + бэкап), вышка-UI переезжает на этап 3+ поверх stovpd.
3. SECURITY-канон — обязательный артефакт до этапа 1.
4. Мета-метрики фабрики — в VISION; ticket-id в job-контекст — требование
   job-модели.
5. T2-08 — отдельное окно, алиасы, приёмка онбордингом реального человека.
6. Календарная рамка и квота окон на стройку — в дорожную карту.
7. Карточки гипотез на 3 ключевые ставки — до этапа 3.
