# nyron-dev — стандарт разработки продукта с флотом агентов

Это не набор утилит. Это **система контролируемого создания продукта**:
общепринятые стандарты разработки заложены внутрь, флоу конфигурируется под
любую команду, а процесс отделён от исполнителя. До сих пор процесс жил в
головах («как мы пишем тикеты» знал тот, кто давно работает); здесь он живёт
в конфигурации — и потому не важно, работает ли один человек, закрывающий все
роли, или несколько людей с разными ролями: флоу один, артефакты одни,
приёмка одна. Это и даёт управляемость продукта — и в дискавери (что делать
и почему), и в деливери (как доставить и чем доказать готовность).

Три слоя системы:

- **Ядро — недоговариваемое.** Работа имеет DoD; находки имеют разбор; ревью
  независимо («кто писал — тот не проверяет»); секреты не в коде; границы
  задачи расширяет постановщик. Конфигом не отключается — это то, что делает
  систему системой.
- **Флоу — конфигурируемое.** Имена статусов и колонок трекера, стадии
  гипотезы, роли, размеры задач, потолок параллели — всё в конфиге проекта.
  Скиллы ходят по ключам, а не по именам, поэтому ложится и Jira с девятью
  колонками, и доска с тремя.
- **Исполнение — свободное.** Кто закрывает роль — человек в Desktop, агент
  в CLI, контейнер в облаке — стандарту всё равно.

Подключение проекта — это приведение к стандарту, а не приём как есть:
анализ → поиск секретов (включая захардкоженные) → секретница → правки
канонов по согласованию → аттестация. Конфигурируется форма, не качество.

Работа в два шага: **продукт** (решить ЧТО делать и написать понятную
задачу) → **доставка** (флот исполняет: код → кросс-ревью другой моделью →
мерж по очереди). Один и тот же плагин едет на разных проектах через
конфиг-файл проекта.

Кроме волн по задачам у фабрики есть **фоновые процессы** — работа, которая
не привязана к тикету и не должна быть похоронена: пассивный рефакторинг
(разбор перечня долга, когда флот свободен) и регулярные e2e-прогоны
(тестирование как процесс, а не только как гейт сдачи). Оркестратор запускает
их в свободные слоты; находки идут обычным путём — тикетами в бэклог.

**Куда это идёт.** Ступень 1 — продукт для системной разработки в одиночку:
профессиональные каноны заложены внутрь, флот из подписок Claude и OpenAI
работает как одна команда. Ступень 2 — сервер команды: все подключаются через
веб-интерфейс (пульт STOVP) и работают в одном флоу; локальный режим — та же
картина, просто сервер стоит на твоей машине.

## Скиллы

### Продуктовый борт (шаг 1 — что делать)

| Скилл | Когда | Что делает |
|---|---|---|
| `intake-groom` | прилетела сырая фича | чистильщик входящих: сырьё → draft-тикет по стандарту силами дешёвой модели + вопросы автору |
| `feature-intake` | «надо добавить такой функционал» | рамка бизнес-требования (**мандат**): файл-требование → согласование → эпик + нарезка задач; тикеты заводит груминг |
| `product-flow` | «есть идея, надо проверить» | цикл гипотезы (**ставка**, HADI): карточка с основанием → челлендж → разворачивание → замер по заявленным метрикам → вердикт-инсайт |
| `team-roles` | «ты — продакт/UX/аналитик…» | ролевые карточки (продакт, UX, дата-аналитик, техлид, SRE, QA); проектные оверрайды из конфига |
| `jira-task-standard` | заведение/груминг любого тикета | стандарт задачи: JTBD, пирамида, без пересечений и без дыр, два слоя, DoD, «Как тестировать» |

### Борт доставки (шаг 2 — исполнить)

| Скилл | Когда | Что делает |
|---|---|---|
| `nyron-waves` | массовое закрытие тикетов эпика | сессия-диспетчер: груминг → волны через /goal-чипы → Jira-шина ревью → мерж по очереди будки |
| `cross-review` | перед сдачей любой ветки | GPT (codex CLI) проверяет код Клода — «кто писал, тот не проверяет»; машиночитаемый вердикт |
| `live-epic-testing` | ручная приёмка эпика живьём | пользователь кликает, сессия мониторит все слои, посекундная разметка, карта флоу, находка = тикет |
| `qa-handoff` | эпик закрыт, передаём QA | сборка одного понятного QA-тикета приёмки |

### Инфраструктура

| Компонент | Что |
|---|---|
| `project-config` (скилл) | конфиг проекта `.claude/nyron-dev.md` (+`.local.md`): тип dev/research, хранилище jira/files, карта моделей, роли, ревьюер |
| `nyron-hub` (MCP-сервер) | «будка»: шина сообщений агентов, бронь файлов, очередь мержа — быстрое служебное МИМО Jira; состояние в `.nyron-hub/` проекта |
| `codex` (MCP-сервер) | GPT как полноценный агент-тул у каждой сессии (`codex mcp-server`): живая делегация задач GPT из диспетчера и волн; конвейерное ревью — по-прежнему скриптом `cross-review` (жёсткий формат вердикта) |

Два продуктовых входа → одна доставка: **мандат** (`feature-intake`, «решено
сделать») и **ставка** (`product-flow`, «верим, надо проверить») сходятся в
груминг и дальше идут одинаково.

Жизненный цикл: **сырьё → intake-groom → продуктовый борт (feature-intake /
product-flow + роли) → jira-task-standard → nyron-waves (+cross-review, +будка)
⇄ live-epic-testing → qa-handoff → эпик закрыт** (у ставки сверху ещё замер и
вердикт-инсайт, питающий следующую гипотезу).

## Установка

Плагин живёт в отдельном репо (канон — GitLab `your2563006/nyron-dev-plugin`,
зеркало — GitHub `lanmiller/nyron-dev-plugin`); детали — README корня репо.

```bash
# Claude Desktop: Settings → Plugins → Add from a repository →
#   lanmiller/nyron-dev-plugin → установить nyron-dev

# Claude Code (терминал):
/plugin marketplace add https://github.com/lanmiller/nyron-dev-plugin
# или локальным клоном:
claude --plugin-dir <клон>/nyron-dev
```

Требования:
- **Jira project-MCP** в `.mcp.json` корня проекта (канон: докерный
  `mcp-atlassian` по API-токену — headless-надёжен; настраивает скилл
  `project-config`, шаблон в его assets; нужен запущенный Docker). Fallback —
  плагинный Atlassian MCP (`plugin:atlassian`) с грантом на сайт проекта;
- **Node 18+** — для MCP-сервера будки `nyron-hub` (zero-deps, докер не нужен);
- **codex CLI** (`npm i -g @openai/codex`, затем `codex login` — браузерный
  вход ChatGPT-подпиской, ОБЯЗАТЕЛЬНО до первого использования) — для
  кросс-ревью `cross-review` и MCP-сервера `codex` (GPT-агент тулом у сессий);
  нет codex/логина — шаг помечается недоступным, не блокер, MCP-сервер просто
  не поднимется;
- git по SSH-ключам к репо проекта (токены не нужны);
- опционально: плагин `superpowers` (brainstorming/writing-plans на груминге);
- опционально: Atlassian REST API-токен в окружении машины — ускоритель
  Jira-вотчеров диспетчера (дефолт плагина — бес-токенный).

Подключение к новому проекту: скилл `project-config` создаёт
`.claude/nyron-dev.md` (канон проекта, коммитится) из шаблона; личные
оверрайды — `.claude/nyron-dev.local.md` (gitignored). В `.gitignore` проекта
добавить `.claude/nyron-dev.local.md` и `.nyron-hub/`.

## Конвенции (сквозные)

- Jira — единственная шина коммуникации: брифы, отчёты, вердикты — комментами.
- Папка эпика: `ai-evolve-docs-test/waves/<DEV-эпик>-<слаг>/` — всё длиннее
  коммента файлами, в тикет — ссылка.
- Канон правил волн: `<docs_dir>/shared/wave-rules.md` — **собирается**
  скриптом `hub/wave-rules-sync.py` из шаблона
  `skills/nyron-waves/assets/wave-rules-template.md` (универсальное), конфига
  проекта (значения) и `<docs_dir>/shared/wave-rules.project.md` (проектное).
  Руками канон не правят.
- Язык — русский; секреты в тикеты и чипы не вписываются.
