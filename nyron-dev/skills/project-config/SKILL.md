# project-config — один плагин, много проектов

Всё «как делать работу» живёт в скиллах плагина и одинаково для всех проектов.
Всё «чем проекты отличаются» живёт в конфиг-файле проекта. Этот скилл — про
чтение и создание конфига.

## Два файла конфига

| Файл | Кто | Git |
|---|---|---|
| `.claude/nyron-dev.md` | канон проекта, общий для команды, БЕЗ секретов | коммитится |
| `.claude/nyron-dev.local.md` | личные оверрайды (тот же формат) | gitignored |

Формат: YAML-фронтматтер (структура) + свободный markdown (заметки проекта для
агентов). Схема полей — `assets/config-template.md`. Значения `.local.md`
накладываются ПОВЕРХ канона по ключам верхнего уровня.

## Чтение конфига (протокол для всех скиллов плагина)

1. Прочитать `.claude/nyron-dev.md` от корня проекта; поверх — `.local.md`,
   если есть.
2. Файла нет → работать по дефолтам ai-evolve (текущие якоря скиллов) И
   предложить пользователю создать конфиг этим скиллом.
3. Ключевые развилки поведения:
   - `storage: jira` → задачи/брифы/отчёты в Jira через `jira.mcp_server`;
     `storage: files` → задачи markdown-файлами в `files.tasks_dir`
     (фронтматтер: status, assignee, ticket-слаг; статусы двигаются правкой
     фронтматтера, отчёты — секциями файла).
   - `type: development` → волны пишут код (git-механика, ветки, MR);
     `type: research` → волны работают с данными: гипотеза → эксперимент →
     замер (флоу — скилл `product-flow`); артефакты — файлы в `docs_dir`,
     git — по ситуации.
   - `models.*` → подставлять в чипы и вызовы субагентов вместо зашитых
     дефолтов.
   - `max_parallel_waves` → сколько сессий-волн запускать одновременно. Эпик
     режется на максимум параллели и упирается в это число; поля нет → 4.
   - `reviewer.engine` → включает/выключает шаг кросс-ревью (скилл
     `cross-review`).
   - `roles.<slug>` → оверрайды карточек скилла `team-roles`.
   - `jira.issue_types` / `jira.labels` / `jira.statuses` → имена типов,
     лейблов и статусов ЭТОГО трекера. Скиллы не хардкодят «Задание/Баг/Эпик»
     и зоны — берут отсюда; поля нет → дефолты ai-evolve (проект DEV).
   - `quality_floor` → что в проекте НЕ минимизируется (стоп-ступени лестницы
     «до кода» у волн). Только `type: development`; поля нет → лестница всё
     равно не срезает флаги, тесты и проверки доступа.
   - `jira.routes` → карта «отдел → куда уходит работа» (ключ проекта, доска,
     канал, папка). Набор отделов НЕ жёсткий: блоки «требования по отделам» и
     маршрутизация тикетов строятся из этой карты, а не из зашитого списка.
     Включаются только вовлечённые отделы.
   - `epic_folder` + `files.requirements_dir` → где лежат папка эпика и
     файлы-требования (скиллы `feature-intake`, `nyron-waves`,
     `jira-task-standard`). Поля нет → дефолт ai-evolve
     `ai-evolve-docs-test/waves/{key}-{slug}`.
   - `files.hypotheses_dir` + `hypothesis_folder` → пакет гипотезы (скилл
     `product-flow`, только `type: research` или смешанные продуктовые треки).
   - `canon_dir` / `canon_index` → память продукта (командная правда: метрики,
     запущенное, аудитория, принципы). Отдельна от session-памяти агента (та —
     указатели) и от движка данных (как достать). Пополняется шагами
     `product-flow`, а не отдельной рутиной.
   - `plugin_version` + `x_<project>.after_plugin_update` → под какую версию
     плагина написан конфиг и что сверить при бампе. Проектные доп-поля
     держать ТОЛЬКО в неймспейсе `x_<project>:` — иначе столкнутся с новыми
     полями плагина.

**Мягкая деградация обязательна:** любого нового поля может не быть в старом
конфиге проекта. Нет поля → работать по дефолту ai-evolve, конфиг не чинить
молча; расхождение схемы — сказать пользователю одной строкой.

## Подключение к проекту — по требованию

Одноразовые шаги (создание конфига, Jira MCP, каноны для codex, будка,
чек-лист переноса на новый проект) — в `references/setup.md`. В повседневной
работе этот файл не читается.

## Секреты

В конфиг секреты НЕ пишутся никогда. Токены (Jira API и прочие) живут в
`.mcp.json` проекта (gitignored) или в окружении машины; конфиг называет только
ИМЯ MCP-сервера, который ими пользуется. Токен нужен — спросить у пользователя,
а не искать в секретницах других проектов.

## Смежные скиллы

- `team-roles` — читает `roles.*` оверрайды отсюда.
- `cross-review` — читает `reviewer.*`.
- `nyron-waves` — читает `storage`, `models`, `type`, `epic_folder` при нарезке волн.
- `intake-groom` — читает `storage` (куда класть черновик задачи).
- `feature-intake` — читает `files.requirements_dir`, `routes`, `epic_folder`.
- `product-flow` — читает `files.hypotheses_dir`, `hypothesis_folder`,
  `epic_folder`, `routes`, `canon_dir`/`canon_index`.
- `jira-task-standard` — читает `jira.issue_types`, `jira.labels`,
  `jira.statuses`, `epic_folder`.
