# vibe — вайбкодинг: скорость вместо конвейера, учёт вместо бюрократии

Третий режим работы плагина (решение CTO 25.08). Класс задач: визуальные и
мелкие правки, где проверка — глаза постановщика на живом стенде, а не тесты:
карточки, вёрстка, ленды, тексты, отступы, состояния компонентов. Скорость
важнее контроля, но два инварианта несгораемы: **след в Jira на финале** и
**контроль догоняет фоном** (Astra-ревью отдельным витком), а не стоит на пути.

## Роль и канал

- Сессия-вайб — **единственный исполнитель**: правит сама, руками, без
  обязательных субагентов и без волн. Субагенты — по желанию, для параллели.
- Постановщик сидит в Desktop/пульте и говорит правки в реальном времени —
  сообщения доезжают мид-тёрн (`pult_send`). Ритм: услышал → поправил →
  «смотри на стенде» → следующая.
- Живой стенд с горячей перезагрузкой — часть режима: постановщик видит
  каждую правку сразу. Стенда нет — поднять первым делом.

## Что ВЫКЛЮЧЕНО (и это законно)

- TDD и написание тестов. Red-тесты, тестгены, полные сьюты — не в этом
  режиме.
- Кросс-ревью на каждую правку, челлендж постановок, брифы, паспорта
  конвейера, волны, вердикты.
- Тикет ДО работы. Jira заполняется на финале, не в начале.

## Что ОСТАЁТСЯ (несгораемое)

- **Лестница до кода в одну строку**: не плодить дубль существующего
  механизма — сначала посмотри, что уже есть.
- **Дизайн-система**: новый кусок UI — в систему компонентов и на витрину,
  не «локально в странице». Вайб, размазавший тот же виджет по трём местам,
  создаёт работу следующему вайбу.
- **Доступы и данные**: правка задевает проверки доступа, платежи, миграции,
  чужие данные → это НЕ вайб — сказать постановщику и увести в обычный контур.
- **Не ломать чужое**: тронул файл с существующими тестами — точечный прогон
  затронутого (не полный сьют). Красный CI по твоей правке — чинится сразу,
  это часть вайба, а не «потом».

## Git-механика

- Правки идут **в main** (стенд — полигон): мелкими коммитами по ходу,
  заголовок `vibe: <что сделано>`. Пуш сразу после связной правки — стенд
  обновляется, откат любой правки = revert одного коммита.
- Перед пушем — быстрый смоук сборки (lint/build затронутого), чтобы main
  не краснел. Конфиг проекта может переопределить ветку (`vibe.branch`),
  дефолт — main.

## Журнал сессии

С первой правки вести журнал (файл в папке эпика/доков или scratch):
одна строка на правку — что, зачем, файлы, коммит. Из него собирается
финальный тикет; «по памяти» на финале не восстанавливать.

## Финал — команда «закругляемся»

По команде постановщика («закругляемся», «всё», «сгружай») строго по порядку:

1. **Зонтик-тикет в Jira**: «Вайб <дата>: <тема>» — перечень правок из
   журнала (что → коммит), стенд и «как посмотреть» по шагам, метка `vibe`.
   Статус — «Готово» (проверено глазами постановщика в живую, это и есть
   приёмка). Тип и статусы — из конфига проекта (`jira.*`).
2. **Astra-ревью фоном — автоматом**, не спрашивая: дифф всей сессии
   (`git diff <SHA-старта>..HEAD`) через `cross-review` (`-s S` или `-s M`
   по размеру диффа, фоновым Bash). Вайб его НЕ ждёт. Находки при получении:
   `[БЛОКЕР]`-класс (реально ломает) → отдельный тикет-баг в бэклог со
   ссылкой на зонтик; остальное → перечень долга проекта. Находки — НЕ
   доработка вайба: прогоняются потом обычным контуром или следующим вайбом.
3. **Сводка постановщику**: что сделано, ссылка на зонтик, «Astra догонит
   фоном — находки упадут тикетами».

Сессия не завершается до п.1–2: вайб без следа в Jira — это правки, которых
через месяц никто не объяснит.

## По ходу вылезло большое

Правка не влезает в вайб (надо копать, менять поведение, трогать бэк с
рисками) — НЕ раздувать сессию: одна строка постановщику + тикет в бэклог,
и дальше вайбить. Вайб длиной в рабочий день — сигнал, что это был не вайб.
