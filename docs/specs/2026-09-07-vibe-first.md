# Переосмысление плагина: вайб — дефолт, флот — отдельно

Статус: проект спеки по разговору с CTO 07.09.2026, на челлендж. Кода нет —
только модель. Источники: разбор `addyosmani/agent-skills` (0.6.9, 25 скиллов),
скилл `vibe` (0.13.0–0.14.2), `hooks/code-policy.md`,
`morda/mcp/orchestrator-context.sh`, `docs/SKILLS-AUDIT.md` (12.08).

## Суть одним абзацем

Единица проектирования плагина меняется: была **флот сессий без человека**
(пульт, будка, сторож, эскалатор, волны), становится **человек за экраном плюс
одна фронтир-сессия**. Контроль переезжает с «до кода» (бриф, паспорт, красный
тест, челлендж плана) на «догоняет» (ревью другой моделью фоном, полный сьют
в CI на пуше, след в трекере на финале). Ядро стандарта не трогается. Флот не
удаляется — уезжает во второй плагин и перестаёт грузиться по умолчанию.

## Зачем: три факта

1. **Пульт не используется.** CTO 07.09: «почти перестал юзать пульт, он
   слишком громоздкий и долгий»; работа идёт в режиме `vibe` на вручную
   выбранной подписке — и днём, и ночью («ставлю вайб и он доезжает»). Факт
   использования важнее любых аргументов «зато ночью».
2. **Цена ошибки упала.** Конвейер проектировался, когда неверная правка
   стоила дорого: тест до кода, паспорт, вердикт до мержа. С Fable как
   исполнителем и Astra как ревьюером неверная правка стоит один `revert`
   мелкого коммита, а находки ревью ловятся фоном (0.14.2: два долга на
   диффе, оба починены).
3. **Стоимость входа не окупается.** Вход в волну — ~7150 слов
   (SKILLS-AUDIT), в каждую сессию — политика кода плюс оркестратор-контекст
   плюс проверка версии. Вход в `vibe` — 240 слов, и этого хватает.

Вывод: три режима (конвейер, волны, вайб) с конвейером по умолчанию —
перевёрнутая пирамида. Дефолтом должен быть тот режим, которым пользуются.

---

## 1. Что не меняется — ядро

Пять строк из README, они не про флот:

- у работы есть след и приёмка;
- находки разбираются, а не теряются;
- ревью независимое: кто писал — тот не проверяет;
- секреты не в коде;
- границу задачи расширяет постановщик, не исполнитель.

Плюс лестница до кода и три проверки из `code-policy.md` — это про качество
кода, а не про способ его доставки.

## 2. Принцип: контроль догоняет

| Было (контроль до) | Стало (контроль после) |
|---|---|
| тикет и бриф до работы | человек ставит голосом в чате; тикет — след на финале |
| красный тест до кода | точечный прогон затронутого в сессии; полный сьют — CI на пуше |
| челлендж плана другой моделью | ревью диффа другой моделью фоном на финале |
| паспорт-гейт на старт сессии | нет; секреты ловит pre-commit и ревью |
| вердикт диспетчера до мержа | коммиты сразу в main (стенд — полигон), откат = revert |

Следствие, которое нельзя пропустить: **у проекта должен быть CI**, иначе
«тесты уходят из сессии» превращается в «тестов нет». CI — предусловие
режима, проверяется скиллом `config` при подключении проекта.

## 3. Состав плагина: пять скиллов

| Скилл | Из чего | Что делает |
|---|---|---|
| `work` | `vibe` + `code-policy.md` | дефолтный режим: одна сессия, живой стенд, мелкие коммиты, точечный смоук, финал со следом и фоновым ревью |
| `review` | `cross-review` | ревью диффа другой моделью: пять осей, severity-метки, машиночитаемый вердикт; скрипты как есть |
| `ticket` | `intake-groom` + `feature-intake` + `jira-task-standard` | «оформи это как задачу по стандарту» — на финале `work` или когда по ходу вылезло большое |
| `hypothesis` | `product-flow` | гипотеза как единица трека (HADI); ужать вдвое |
| `config` | `project-config` | только значения проекта; установка — в README |

`team-roles` → папка `references/roles/`, читается по запросу, скиллом не
является. `live-epic-testing` и `qa-handoff` → в `nyron-fleet` (это приёмка
эпика, а эпик — единица флота).

### 3.1 `work` — что впитывает из agent-skills

Из `addyosmani/agent-skills` берутся три вещи и ни один процесс:

1. **Операционные правила** (из `using-agent-skills`), полстраницы: озвучь
   допущения до правки; при противоречии — стоп и вопрос, а не догадка;
   не расширяй scope; «кажется верным» — не доказательство; не поддакивай
   плохому решению. В вайбе без тестов это и есть замена тестам.
2. **Таблица рационализаций** — отмазки, которыми модель срезает смоук
   сборки, границу по данным и фоновое ревью, с ответом на каждую. Аудит
   12.08: агент читает описание и не идёт в тело скилла; таблица держит
   именно здесь.
3. **Red flags и Verification** как обязательные секции скилла.

Не берётся: роутер, слэш-команды, TDD, спека до кода, план до спеки.

### 3.2 `work` — ночной режим

Вайб-сессия, упёршаяся в вопрос, ночью стоит до утра. Правило: если
постановщик недоступен (явно сказано «на ночь» или нет ответа дольше
порога), сессия **не спрашивает — принимает решение**, пишет его в журнал
с пометкой «решено без постановщика», и подсвечивает в утренней сводке
отдельным блоком. Граница по данным и доступам (§3.3) ночью не снимается:
упёрся в неё — останавливаешься и ждёшь утра, это единственный законный
ночной стоп.

### 3.3 Граница режима — единственная жёсткая линия

Правка задевает проверки доступа, платежи, миграции, чужие данные — это НЕ
`work`. Сессия говорит об этом постановщику и ждёт явного решения: делать
здесь с усиленным ревью до мержа, или уводить во флот. Для psylia
(данные пользователей Telegram) и биллинга ai-evolve линия не обсуждается.

### 3.4 `review` — что впитывает

Пять осей из персоны `code-reviewer` (корректность, читаемость,
архитектура, безопасность, производительность) и метки severity
(Critical / Required / Optional / Nit) — как содержание промпта ревьюеру.
Сейчас ревьюер получает формат вердикта, но не критерии. Формат вердикта и
выбор ревьюера по автору (`-e auto`) не меняются.

### 3.5 След в трекере — легче

Зонтик «Вайб <дата>: <тема>» остаётся, но собирается механикой: список
коммитов `vibe:` за сессию (`git log <SHA-старта>..HEAD`) плюс «как
посмотреть» в две строки. Журнал руками не ведётся — коммиты и есть журнал.
Конфиг проекта решает, нужен ли тикет вообще (`trace: jira | changelog |
none`).

## 4. Флот — второй плагин `nyron-fleet`

Уезжают целиком: `nyron-waves` с протоколом и шаблонами, `live-epic-testing`,
`qa-handoff`, `hub/` (будка, сторож, нянька, эскалатор), Stop-хук взвода
вотчера, оркестратор-контекст пульта. Пульт (`morda/`) — свой репо или
папка того же.

Не удаляется: код рабочий, замеры (DEV-1210, KAN-209) и решения в нём
живые. Кому нужна параллель по эпику или ночной прогон без единой сессии —
ставит второй плагин; `work` тогда говорит «это во флот» по §3.3.

Что это даёт сразу: в SessionStart грузится один блок вместо трёх, будка не
блокирует засыпание сессии, в `.mcp.json` плагина остаётся только `codex`.

## 5. Требования к скиллам (анатомия)

Каждый из пяти скиллов:

- фронтматтер: `name` + `description` ≤ 600 знаков, без пересказа метода
  (чек-лист SKILLS-AUDIT, ловит `hub/skills-lint.py`);
- секции: зачем → когда (и когда НЕ) → процесс → рационализации → red
  flags → verification;
- тело ≤ 600 слов; справочники — отдельными файлами по требованию;
- **evals на срабатывание**: по три позитивных и два негативных промпта на
  скилл в формате `evals/cases/<skill>.json` (формат agent-skills tier 2).
  С пятью скиллами проверка «повайбим / оформи тикет / прогони ревью
  / есть гипотеза / настрой проект» попадает куда надо — за вечер.

## 6. Миграция — по шагам, без переписывания за раз

1. **Перевернуть дефолт** (одним релизом, minor): оркестратор-контекст из
   SessionStart в opt-in; `vibe` объявлен режимом по умолчанию в README и
   `code-policy.md`; ночное правило §3.2. Ничего не удаляется.
2. **Вынести флот**: `nyron-fleet` как второй плагин в этом же маркетплейсе;
   у пользователей волн ничего не ломается — ставят оба.
3. **Слить скиллы**: `work`, `ticket`, `config` по §3; `team-roles` в
   референсы. Старые имена — алиасами в описаниях на один релиз.
4. **Анатомия и evals** по §5.
5. **Замер через месяц**: сколько блокеров ловит фоновое ревью по
   вайб-диффам. Около нуля — режем церемонию дальше. Не ноль — граница §3.3
   сдвинута слишком далеко, видно по фактам.

Шаг 1 можно выкатить сегодня; шаги 2–3 — отдельные релизы, каждый с бампом
в двух манифестах (правило репо; сейчас `marketplace.json` отстал:
0.11.0 против 0.14.2 в `plugin.json`).
