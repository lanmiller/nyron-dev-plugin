AGENTS.md) не тронут — переписание только после «да» по этому макету.
Закон домов — SYSTEM-DESIGN §7; здесь его первый работающий кусок:
попроектный конфиг инструментов, ключница и верификатор фактом.

## Суть одним абзацем

Проект носит свой паспорт в git: файл `.claude/passport.json` перечисляет,
что проекту нужно для работы с плагином (MCP-серверы и их смоуки, плагин и
скиллы с минимальной версией, имена ключей с комментариями). Сами ключи
живут ТОЛЬКО в ключнице `<проект>/.secrets/` (gitignored). `.mcp.json`
становится указателем без значений: команды MCP-серверов запускаются через
загрузчик, который подставляет переменные из ключницы. Пульт по кнопке
«проверить готовность» прогоняет паспорт фактом и на каждый красный пункт
даёт конкретный шаг починки.

## Файлы в репозитории проекта

| Файл | Едет в git | Что в нём |
|---|---|---|
| `.claude/passport.json` | да | требования проекта: MCP + смоуки, плагин + скиллы + min-версия, реестр ключей (имена и комментарии, БЕЗ значений), требование забора |
| `.secrets/` | НЕТ (gitignored) | ключница: файлы `<имя>.env` (`KEY=VALUE`), все токены/ключи проекта |
| `.mcp.json` | да, когда очищен от секретов | указатель: команды через загрузчик ключницы; значений секретов нет |
| `.claude/nyron-dev.md` | да (существует) | конфиг плагина — не меняется этим шагом |

Переносимость правильным зерном (закон §7): новая машина = скопировать
`.secrets/` — проект живой. Ключи НИКОГДА не уезжают в git; `.env` и
`.mcp.json` — указатели, не значения.

## Схема .claude/passport.json

```json
{
  "version": 1,
  "plugin": {
    "name": "nyron-dev",
    "marketplace": "nyron-dev-marketplace-v2",
    "min_version": "0.9.2",
    "skills": ["project-config", "jira-task-standard", "cross-review",
               "nyron-waves", "team-roles"]
  },
  "mcp": {
    "jira-nyron": {
      "keys": ["jira.env"],
      "smoke": { "tool": "jira_get_user_profile",
                 "args": { "user_identifier": "$JIRA_USERNAME" } }
    }
  },
  "keys": {
    "jira.env": {
      "JIRA_URL": "адрес Jira, например https://nyron.atlassian.net",
      "JIRA_USERNAME": "корп-почта пользователя",
      "JIRA_API_TOKEN": "секрет: id.atlassian.com → Security → API tokens",
      "CONFLUENCE_URL": "адрес вики: <JIRA_URL>/wiki",
      "CONFLUENCE_USERNAME": "та же корп-почта",
      "CONFLUENCE_API_TOKEN": "тот же API-токен"
    }
  },
  "guard": true
}
```

Пояснения:

- `keys` — это «.env.example с комментарием к каждой переменной» из
  требований тикета, только структурой: значение поля = комментарий,
  значения секретов здесь не бывает. Верификатор сверяет ключницу по
  именам, не читая значений наружу.
- `mcp.<имя>.smoke` — как проверить сервер ФАКТОМ: вызов инструмента,
  а не галочка «настроен». В аргументах работает подстановка `$ИМЯ` из
  env-файлов этого сервера — сам паспорт значений не носит.
- `guard: true` — проекту обязателен забор-хук раннера (bypass без забора
  не включается); сам файл забора — принадлежность машины (morda), не
  проекта.
- Сканер требований по спеке («нашёл Jira → нужен токен») в v1 не
  автоматика: список собирается при подключении проекта аудитором;
  структура к автоматике готова.

## Ключница .secrets/

- Формат: файлы `<имя>.env`, строки `KEY=VALUE`, без экспортов и кавычек.
- `.gitignore` проекта обязан содержать `.secrets/` — верификатор проверяет
  это фактом (`git check-ignore`), а не доверием.
- Читают её только загрузчик MCP и хуки/флоу проверки кода. Секретницы
  других проектов и разбросанные env машины — вне закона.

## Загрузчик: morda/keys/with-keys.mjs

`.mcp.json` не умеет секреты — он получает команду-обёртку:

```json
{
  "mcpServers": {
    "jira-nyron": {
      "command": "node",
      "args": ["morda/keys/with-keys.mjs", ".secrets/jira.env", "--",
               "python3", "nyron-dev/hub/jira-slim.py", "docker", "run", "…"]
    }
  }
}
```

Загрузчик читает env-файлы ключницы (пути — от текущего каталога, то есть
корня проекта), кладёт переменные в окружение и запускает настоящую
команду насквозь (stdio не трогает). Один загрузчик обслуживает все
проекты машины — в чужие репо он не копируется, путь в их `.mcp.json`
указывает на клон плагина (тот же приём, что с jira-slim.py сегодня).

## Верификатор в пульте — «проверить готовность»

Кнопка у проекта на странице /settings. Каждый пункт — факт, красный
пункт — карточка с шагом починки, молчаливых фолбэков нет:

| № | Пункт | Как проверяется фактом | Шаг починки при красном |
|---|---|---|---|
| 1 | Паспорт | `.claude/passport.json` читается и валиден | «создай паспорт: …/passport.json (пример — nyron-dev-plugin)» |
| 2 | Ключница | `.secrets/` есть; `git check-ignore .secrets` = игнорится; каждый файл из `keys` существует; каждая переменная непуста | «положи файл X с переменными Y (комментарии — в паспорте)» |
| 3 | Секреты не в git | `git ls-files .secrets` пуст; `.mcp.json` не содержит значений секретных паттернов (ATATT…, sk-…, ghp_…, BEGIN…KEY) | «вынеси значение из .mcp.json в ключницу и ротируй токен — git-история скомпрометирована» |
| 4 | MCP отвечает | для каждого сервера паспорта: запуск команды из `.mcp.json`, initialize + вызов смоук-инструмента, ответ без ошибки | «сервер X не ответил: <стдерр/причина>; проверь Docker/ключи» |
| 5 | Плагин и скиллы | установленная копия `~/.claude/plugins/cache/<marketplace>/<name>/<ver>/`, версия ≥ min_version, каждый скилл из списка на месте | «установи/обнови плагин: /plugin marketplace add …» |
| 6 | Забор отвечает | guard-хук на тестовый вход (`sudo …`) возвращает deny; на мусорный вход — тоже deny (fail-closed) | «забор сломан: morda/guard/pretooluse-guard.mjs — bypass закрыт до починки» |

Результат прогона — живое состояние (дом «пульт»): нигде не сохраняется
как истина, каждый прогон заново. Значения секретов в выводе не
показываются никогда — только имена и статус «задано / не задано».
