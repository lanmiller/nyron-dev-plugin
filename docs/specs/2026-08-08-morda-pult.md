## Целевая картина (формула CTO)

**Локальные Клоды — администрация, серверные контейнеры — производство,
сессии — командный актив.**

У члена команды: Claude Desktop (личный инструмент) + морда (рабочая
панель). На сервере — флот контейнеров: Claude Code CLI по одному на
контейнер, каждый на своей подписке; рядом контейнеры codex (и любые
другие CLI-агенты — механизм терминальный, не протокольный). Человек в
морде находит задачу, говорит «делаем» — система подбирает свободный
контейнер и открывает там диспетчерскую сессию. После закрытия эпика
остаётся история: какие таски, какая сессия какую делала; любой
разработчик может обратиться к той сессии — она на сервере, а не умерла
с чьим-то ноутбуком.

## Части системы

| Часть | Обязанность | Фаза 1 | Фаза 2 |
|---|---|---|---|
| tmux | запуск сессий, ввод внутрь, attach руками | на машине CTO | внутри каждого контейнера |
| Транскрипт `.jsonl` | источник окна: маркдаун + структура (инструменты, субагенты, воркфлоу) | `~/.claude/projects/` | тома контейнеров на сервере |
| Будка (hub.db) | запросы `ask`, ответы `decision`, штамп базы, связь с тикетом | файл на проект | сервис по сети |
| Надзиратель | состояния сессий, ловля молчунов, перепубликация витрины | Haiku headless по расписанию | тот же контур на сервере |
| Морда | вкладки проектов, зона «ждут вас», окно/терминал/экран сессии, запуск новых | SvelteKit локально, слушает 127.0.0.1 | та же папка на сервере, за VPN |
| Будильник | доставка ответа живой сессии; подъём осиротевшей работы новой сессией | внутри морды | дёргает контейнеры |
| Гонец | эскалация в Телеграм | внутри морды | без изменений |
| Витрина | артефакт-сводка, перепубликуется надзирателем | опционально | основной вид «с телефона» |

Ключевые решения по частям:

- **Морда не читает hub.db и транскрипты напрямую** — через тонкий слой
  доступа (встроенный Node-сервер SvelteKit). В фазе 2 меняется только он.
- **Надзиратель — отдельный процесс**, не часть морды: морду закрывают,
  надзор идёт всегда.
- **Артефакт мордой быть не может**: песочница артефактов запрещает
  сетевые запросы к локальной машине. Артефакт — только витрина
  (read-only сводка), пульт — локальная страница.
- **Окно рисуется из транскрипта, не из пикселей терминала**: транскрипт —
  это маркдаун плюс структура; tmux нужен только для ввода и attach.
  Проблемы ширины экрана и разбора спиннеров не существуют.
- **Мост tmux → браузер** (для вкладки «Терминал»): выбор ttyd / свой на
  node-pty — ОТЛОЖЕН, проектируем сменным.

## Три канала сессии в морде

| Канал | Что это | Когда нужен |
|---|---|---|
| Окно | транскрипт красиво: маркдаун, инструменты-плашки, дерево субагентов | читать и отвечать — основной |
| Терминал | tmux как есть | перехватить управление руками |
| Экран | общий браузер контейнера (noVNC) | смотреть глазами агента, кинуть картинку, тыкать вместе |

Экран — требование фазы 2 (в фазе 1 браузер агента и так открыт окном на
той же машине). Контейнер фазы 2 = CLI + tmux + Chromium на виртуальном
дисплее + noVNC наружу. Агент управляет тем же Chromium своими
браузер-тулами через отладочный протокол — браузер физически один, две
пары рук без синхронизации. Файлы сквозь VNC не ходят: «кинуть картинку» =
ручка загрузки в тонком слое → файл падает в папку контейнера → агент
видит путь, в браузере доступен через диалог.

## Запрос на решение (`ask`) — сообщение будки

Обязательные поля:

- **Вопрос одной строкой** — что именно решить;
- **Варианты** — 2–4, каждый со следствием в одну строку; отвечать можно
  номером;
- **Контекст на один экран** — что сделано, что упёрлось, почему сейчас;
- **Штамп базы** — repo + sha + время среза (решение из PILOT 08.08);
- **Ссылки** — тикет и session ID;
- **Срочность** — «блокирует» / «может подождать».

Ответ (`decision`): выбранный вариант или текст, кто решил, когда.

Правило для сессий: задал вопрос человеку в чате — обязан продублировать
`ask` в будку. Надзиратель ловит нарушителей.

## Состояния сессии (ставит Haiku-надзиратель)

Надзиратель — headless `claude -p` на Haiku по расписанию (контур проверен
фактом на STOVP-40). Читает ХВОСТЫ транскриптов + будку, а не полные логи.

| Состояние | Признак | Реакция морды |
|---|---|---|
| работает | последние события — инструменты, генерация | зона «идёт работа» |
| ждёт решения | оформлен `ask` | карточка в «ждут вас», таймер |
| ждёт молча | в транскрипте вопрос/остановка, `ask` нет | надзиратель заводит `ask`-заглушку + пометка нарушителю |
| замолчала | ни событий, ни `ask` дольше порога (волна 30 мин, чип 15) | карточка «проверить» |
| умерла | процесса в tmux нет | остался открытый `ask`/тикет → карточка «работа осиротела» + кнопка «поднять новую» |

Определение «ждёт/молчит» — задача модели, не эвристики: правила по тексту
врут, дешёвая модель читает хвост надёжнее.

## Гонец — эскалация в Телеграм

1. Карточка в морде — сразу.
2. Телеграм — «блокирует» без ответа > 30 мин; «может подождать» > 2 ч.
3. Повтор — не чаще раза в час, ОДНИМ сообщением-сводкой, не россыпью.

Правило тишины: ночью гонец молчит, кроме пометки «горит» (ставит человек
в брифе или `ask` с явным основанием).

## Будильник — доставка и подъём

- Живой сессии ответ доставляется `send-keys` в её tmux. Признак «готова
  принять ввод» берётся из транскрипта (последнее событие — ответ модели),
  не из экрана.
- Мёртвой — новая сессия с брифом = `ask` + `decision` + штамп базы.
- **Первое обязательное действие поднятой сессии — `git fetch` и сверка с
  `origin/main`**: не писать отчёт про мир, которого нет (урок KAN-109).
- Чипы `spawn_task` в CLI-мире заменяются кнопками морды: сессия пишет в
  будку «нужна сессия под тикет с брифом», морда показывает кнопку, клик
  остаётся за человеком. Запуск — `tmux new-session` (или `claude agents`).

## Реестры (фаза 2, схема закладывается в фазе 1)

**Реестр сессий** (бывший «проект Б — паспорт волны»): тикет ↔ сессия ↔
человек ↔ контейнер/машина ↔ путь транскрипта ↔ штамп базы. Заводится при
запуске из морды. История эпика = выборка из реестра.

**Реестр контейнеров**: подписка, занят/свободен, чем занят, остаток
лимитов. Лимиты снимаются точно, через сам CLI: экран `/usage` показывает
проценты сессионного окна, недели и недели по модели плюс время сброса
(проверено на 2.1.206). Отдельной shell-команды нет, но контейнер держит
Claude в tmux — планировщик шлёт `send-keys '/usage'`, снимает
`capture-pane`, парсит. Каждый контейнер = своя подписка, значит его
`/usage` = состояние именно этой подписки. Подбор контейнера — алгоритм
над реестром, не ИИ.

**Правило одного писателя**: в живую сессию пишут только через морду (она
сериализует ввод); спящую любой поднимает resume/fork.

## Код в контейнерах

**Правда — только origin (GitLab); контейнеры — расходники.** Сделанное
существует после пуша ветки, контейнер можно убить без потерь (кроме
недопушенного черновика).

- В одном контейнере несколько проектов — зонтичные чекауты папками
  (`/work/ai-evolve`, `/work/psylia`, …). Выбор проекта = cwd сессии:
  будка, конфиг nyron-dev.md и .mcp.json уже резолвятся по cwd — ни
  одного нового механизма. Планировщик: `tmux new-session -c <папка>`.
- Копии кода: базовый чекаут (точка входа; `git fetch` при каждом старте
  сессии) → worktree под тикет от свежего origin/main (сносится
  release-шагом) → origin (правда). Схема волн переезжает как есть.
- Изоляция параллельных задач — worktree, не контейнер: в одном
  контейнере может жить несколько tmux-сессий в разных папках.
- Свежесть «чтобы бились»: штамп базы в каждом сообщении; `git fetch` +
  сверка с origin/main перед выводами; ветка пушится сразу; реестр
  показывает отставание чекаутов от origin/main в коммитах
  (`git rev-list --count`).
- Заведение контейнера (разово, руками): SSH-ключи к репам, .mcp.json с
  токенами, логин подписки.

## Безопасность

- Фаза 1: сервер морды слушает только 127.0.0.1, паролей нет.
- Фаза 2: морда — руки, не глаза; минимум токен + HTTPS, правильно — VPN
  (Tailscale). Аутентификация подписки в контейнере — разовая настройка
  при заведении каждого.

## Границы и что НЕ делаем

- Морда показывает флот агентов, не всю команду: методолог в продукте и
  дизайнер в макетах в неё не попадают (решение CTO: подумаем позже).
- Не пишем в чужие живые Desktop-сессии: у сессии один владелец процесса;
  resume при живом окне = гонка двух писателей. Desktop-сессии видны
  зеркалом транскрипта, без ввода.
- Не парсим экран tmux ради смысла — смысл только из транскрипта и будки.
- Не строим свой харнесс поверх stream-json — отказ от этого пути
  зафиксирован: показываем настоящий Claude Code, а не перерисовываем его.
- Витрина-артефакт не получает кнопок действия.

## Порядок строительства (фаза 1, этапы сдаются по одному)

1. **`ask`/`decision` в будке** + правило дублирования вопроса + штамп
   базы в каждом сообщении (само по себе закрывает половину ночной боли).
2. **Надзиратель**: Haiku-контур по расписанию, состояния, заглушки-`ask`,
   витрина-артефакт.
3. **Морда-список**: SvelteKit, вкладки проектов, зона «ждут вас», ответ
   номером варианта → будка → будильник доставляет.
4. **Окно**: рендер транскрипта (маркдаун + плашки инструментов + дерево
   субагентов), ввод через tmux.
5. **Терминал**: мост в браузер (выбрать ttyd / node-pty на этом шаге).
6. **Гонец**: Телеграм по правилам эскалации.

Фаза 2 (сервер, флот, реестры, экран-канал) — отдельная спека после
обкатки фазы 1: переезд будки в сервис, контейнерный образ
(CLI+tmux+Chromium+noVNC), реестры, VPN.
