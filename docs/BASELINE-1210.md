# Замер «до»: эпик DEV-1210, снят 12.08.2026

Снят по истории статусов Jira ДО выката правок. Нужен, чтобы «стало лучше» было
цифрой, а не ощущением. Тот же расчёт повторяется на Блоке 4.

## Что получилось

| Показатель | Значение |
|---|---|
| Тикетов в эпике | 47 (до Ревью доехали 27) |
| Среднее число заходов в Ревью на тикет | **1,74** |
| Доля тикетов, вернувшихся на второй круг и дальше | **44 %** |
| Тикетов с 3–4 заходами | 6 |
| Медиана «В работе → первый Ревью» | **3,7 ч** (максимум 73,5 ч) |
| Медиана хвоста доработок (первый Ревью → последний) | **10,6 ч** (максимум 20,8 ч) |

## Главный вывод

**Работа занимает 3,7 часа, а круги ревью после неё — ещё 10,6.** Почти три
четверти времени тикета уходит не на то, чтобы сделать, а на то, чтобы
дозакрыть замечания. Это и есть цена ревью без границ: каждый круг рождает
новые находки, а вердикт «доработка» выносился по любому замечанию.

Отсюда и приоритет правок: не «писать код быстрее», а **обрубить хвост
доработок** — вердикт только по блокерам в границах тикета, глубина один слой,
потолок семь замечаний.

## Что меряем на Блоке 4 (тот же расчёт)

| Показатель | Сейчас | Цель |
|---|---|---|
| Заходов в Ревью на тикет | 1,74 | ≤ 1,3 |
| Доля вернувшихся на второй круг | 44 % | ≤ 25 % |
| Хвост доработок, медиана | 10,6 ч | ≤ 4 ч |
| Тикетов с 3+ заходами | 6 из 27 | 0–1 |
| Замечаний за один прогон ревьюера | не ограничено | ≤ 7, все с меткой и границей |
| Тикетов, выросших за зону брифа | не считалось | видно строкой в отчёте волны |

Первые три показателя считаются автоматически по истории статусов, последние
три — глазами по отчётам волн.

## Как повторить расчёт

Забрать детей эпика с историей изменений (`jira_search`, `expand=changelog`) и
посчитать по полю статуса: число переходов в «Ревью» на тикет, время от первого
«В работе» до первого «Ревью», время от первого «Ревью» до последнего.
