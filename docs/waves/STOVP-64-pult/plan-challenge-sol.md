ПЛАН: РИСКИ.

1. Категория 4 — волна 3 фактически зависит от WS-инфраструктуры волны 2 и не может безопасно идти параллельно — пруф: production сейчас запускает `node build` (`morda/package.json:6–12`) и `$MORDA/build/index.js` (`morda/install-launchd.sh:37–45`), а Vite не содержит upgrade-плагина (`morda/vite.config.js:4–11`) — грозит dev-only `/ws/browse`, конфликтами в `server.mjs`/`vite.config.js`/`package*.json`/launchd и отсутствующим «тикетом-хвостом» — поправить: вынести общий WS-host в фундаментальную волну перед 66 и 68 либо запускать 68 только после мержа 66; явно добавить `vite.config.js` и `package-lock.json` в карту файлов.

2. Категория 3 — новый WS-слой обходит существующие Basic-auth и CSRF-границы — пруф: пароль проверяется только SvelteKit-хуком `handle()` (`morda/src/hooks.server.js:49–67`), мутации REST защищает `guarded()` (`morda/src/lib/server/guard.js:1–9`); upgrade в `server.mjs` не проходит ни через один из них — грозит удалённым управлением tmux и браузером через туннель; проверка одного префикса `stovp-*` удостоверяет цель, но не клиента — поправить: общий `authenticateUpgrade` с Basic-auth и проверкой `Origin/Host`, затем резолв имени только через `runner.json`; покрыть отказ без auth и с чужим Origin тестами.

3. Категория 1 — STOVP-67 не может быть «только потреблением» текущего git API: worktree по принятой конвенции имеет глубину 3 — пруф: `repoPath()` запрещает глубину больше 2 (`morda/src/lib/server/git.js:79–86`), а API принимает лишь клиентские `project + repo` (`morda/src/routes/api/git/+server.js:9–20`) — грозит ошибкой либо показом диффа main вместо диффа конкретной сессии — поправить: добавить session-aware серверную операцию, которая берёт `cwd` из транскрипта/реестра и сверяет его с `git worktree list`; расширить карту файлов и тесты API.

4. Категория 2 — индекс 65 дублирует уже существующий канонический пофайловый индекс транскриптов — пруф: общая реализация прямо объявлена единственной (`nyron-dev/hub/transcript.mjs:1–8`), `metaCache` уже хранит `mtime/size/meta` (`:97–149`) — грозит двумя расходящимися источниками истины. Дополнительно текущая страховочная сигнатура смотрит один точный каталог (`morda/src/lib/server/fleet.js:311–329`), тогда как канон читает все root/worktree-каталоги по префиксу (`transcript.mjs:35–40`) и сохраняет `cwd`, `entrypoint`, tail-based custom-title (`:122–149`) — поправить: развивать индекс в `transcript.mjs` и экспортировать его в morda либо оставить там метаданные, а в morda индексировать только activity; сохранить фильтрацию по `cwd`, слоты и поздние custom-title.

5. Категория 5 — raw PTY-поток не поддерживается текущим терминальным UI — пруф: `TmuxPanel` удаляет управляющие последовательности и рисует статический `<pre>` (`morda/src/lib/TmuxPanel.svelte:17–44,109–114`), сервер отдаёт snapshot через `capture-pane` (`morda/src/lib/server/runner.js:703–709`), а terminal emulator в зависимостях отсутствует (`morda/package.json:13–30`) — грозит сломанными курсором, очисткой экрана, полноэкранными TUI и resize — поправить: включить xterm.js-подобный эмулятор с протоколом output/input/resize либо отказаться от raw `node-pty` и оставить snapshot-модель; зафиксировать выбор и зависимости в плане.

6. Категория 5 — «поллинг только для мёртвых» ломает живые Desktop/чужие tmux-сессии — пруф: продукт явно поддерживает `desktop` и `mirror` без runner-записи (`morda/src/lib/server/fleet.js:867–895`), `/api/session` возвращает `runner: null` для них (`morda/src/routes/api/session/[project]/[key]/+server.js:9–14`), сейчас все окна обновляются раз в 5 секунд (`morda/src/routes/s/[project]/[key]/+page.svelte:147–190`) — грозит замершей лентой живой нерэннерской сессии — поправить: отдельная подписка `/ws/session/<project>/<key>` независимо от `/ws/term/<name>` либо сохранение polling для любой сессии без подтверждённого session-WS.

7. Категория 5 — поле `ticket` не доведено через restart/reuse и не может быть прочитано текущим `toEpic()` — пруф: `toEpic(ticket)` не знает sessionId (`morda/src/lib/server/fleet.js:370–373`), `runnerOwned()` отдаёт только `{name, alive}` (`:755–768`), `runnerStart()` целиком перезаписывает запись (`morda/src/lib/server/runner.js:386–396`), а `runnerResume()` не передаёт ticket (`:455–469`) — грозит потерей явного тикета после resume/retune и возвратом к ненадёжному разбору текста — поправить: сохранять прежнюю мету записи при рестарте, передавать ticket во все start/resume/adopt-пути и отдавать его через `runnerOwned`; добавить ticket в `pult_start` MCP-схему.

8. Категория 1 — предпосылка «persistent browser-context, как в judge.js» ложна — пруф: `judge.js` запускает одноразовый Playwright CLI `screenshot` через `execFile`, без `chromium`, context, page registry или persistent profile (`morda/src/lib/server/judge.js:205–252`) — грозит сильно недооценённым lifecycle: запуск браузера, user-data-dir, восстановление после падения, страницы нескольких вкладок и закрытие процесса — поправить: описать этот lifecycle как новую инфраструктуру `browser.js`, включая владельца page/session, reconnect и cleanup; не считать `judge.js` готовым механизмом.

9. Категория 1 — одного HTML-файла для MCP Apps недостаточно, текущий MCP его отдать не умеет — пруф: initialize объявляет только `tools` (`morda/mcp/pult-mcp.mjs:146–151`), `tools/list` не отдаёт `_meta`, `tools/call` возвращает только text (`:157–164`), обработчиков `resources/list/read` нет; реальные имена действий — `pult_send`/`pult_judge`, не `queue_add`/`judge` (`:97–127`) — грозит обычным текстовым тулом без виджета и неработающими кнопками — поправить: явно включить MCP resource URI, `resources/read`, нужный MIME, tool `_meta.ui.resourceUri`, `structuredContent` и вызовы существующих MCP-тулов.

10. Категория 3 — обязательные env-флаги для flow-правок отсутствуют — пруф: новые циклы сейчас подключаются безусловно при импорте hooks (`morda/src/hooks.server.js:70–85,126–150,153–168`), запуск идёт напрямую в `runnerStart` (`morda/src/routes/api/runner/+server.js:30–70`), а план не задаёт ни одного флага — грозит невозможностью отдельно откатить WS, browser, новый launch-flow или push после пересборки 4747 — поправить: добавить серверные capability/env-флаги минимум для 66, 68, 69, 70 и 72; UI получает capabilities и сохраняет старые polling/start-пути при `off`. Проверки нужны в обоих состояниях.

11. Категория 5 — уведомление «новый ask/вердикт» не определено как переход состояния — пруф: `overview` берёт `hub.asks({})` (`morda/src/lib/server/fleet.js:192–204`), а вызов без статуса включает `open`, `answered`, `delivered` (`nyron-dev/hub/hub-db.mjs:338–346`); у судьи есть ручной путь через API и фоновый путь через hooks (`morda/src/routes/api/runner/+server.js:52`, `morda/src/hooks.server.js:141–145`) — грозит пушами по старым/уже решённым asks после рестарта и разным поведением ручного и автосудьи — поправить: на старте засевать `seen ask_id` без отправки, дальше реагировать только на появление `status=open`; событие `stuck` испускать из общего результата `judgeStuck`, а не только фонового цикла.
