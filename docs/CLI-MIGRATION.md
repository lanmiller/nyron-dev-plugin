## Этап 0 — прототип на один вечер (ничего не ломает)

Одна волна запускается НЕ чипом, а раннером: tmux-сессия с `claude`, цель
подаётся вводом, жизнь читается из транскрипта (парсер готов). Проверяем
четыре факта: цель доезжает; ответ из пульта доезжает; стоп безопасен;
`--resume` поднимает с контекстом. Отдельно проверить два «непроверенных»:
картинки в CLI; `~/.codex/auth.json` доступен из такой сессии.

Приёмка: волна прожила тикет целиком без Desktop.

## Этап 1 — раннер: пульт владеет процессом

- Реестр процессов: запуск (tmux-сессия на исполнителя), стоп, резюм,
  здоровье (жив/молчит/упёрся в лимит по `rate_limit_event`).
- Кнопки в пульте: «запустить волну» (вместо ручного чипа), «остановить»,
  «поднять резюмом».
- Разрешения: режим без диалогов + **забор-хук обязателен ДО включения** —
  снос вне worktree, силовой пуш, выход за корень проекта, правки на серверах.

Приёмка: волна запускается из пульта; зависшая лечится стоп+резюм из пульта,
а не Esc руками.

## Этап 2 — чат в пульте

Приёмка: рутинный диалог с волной целиком в пульте, с телефона тоже.

## Этап 3 — перевод флота и снос подпорок

Волны и диспетчеры рождаются ТОЛЬКО раннером. Тогда сносим то, что было
подпорками недоступности процессов:
- вотчеры на пробуждение → прямое пробуждение резюмом/вводом;
- Stop-хук перевзвода и нянька → не нужны (пульт видит процесс сам);
- надзиратель-опрос моделью → здоровье из реестра процессов.
Будка ОСТАЁТСЯ как шина смысла (посты, брони, очередь мержа) — уходит только
её роль будильника.

Приёмка: новый эпик от груминга до «флот распущен» без единого ручного чипа
и без Esc; замер параллельности против 1,7×.

## Этап 4 — очередь и ресурсы

Самотянущая очередь (свободен слот → следующая подзадача без зависимостей),
пул аккаунтов (`setup-token` на исполнителя), парковка по лимиту с
авто-резюмом после отката окна, последний акт эпика (сводка → освобождение →
глушение → уборка), фоновые процессы в свободные слоты (пассивный
рефакторинг, регулярные e2e).

Приёмка: mera успеха эпика STOVP-58 целиком.

## Риски, названные заранее

1. **Забор до свободы**: включать режим без диалогов раньше забора-хука
   нельзя — это единственный этапный порядок, который менять запрещено.
2. **Лимиты**: раннер обязан читать `rate_limit_event` и парковать, иначе
   флот молча упирается (как сторож 15.08).
3. **Картинки в CLI** — непроверено; если плохо, дизайн-такты остаются в
   Desktop, это штатно.
4. **tmux против child-process** — решить на этапе 0 по факту: tmux даёт
   бесплатный терминал для ручного захода, child со stream-json — чистый
   поток событий. Возможен гибрид.
