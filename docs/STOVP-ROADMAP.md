# STOVP: где мы, что открыто, что строим

Составлено 11.08.2026 по итогам рабочего дня с CTO. Документ отвечает на три
вопроса: **что уже работает**, **какие вопросы мы задали и чем они кончились**,
**какими эпиками закрывать остальное**.

---

## Вывод первым

1. **Рамка сменилась.** Строим не «пульт над Claude Desktop», а **рабочее место
   в браузере**: заходишь во вкладку — и работаешь. Тогда безразлично, где
   машина: Мак, сервер, телефон.
2. **Потолок Desktop уперся в три вещи** — нажать форму вопроса, вложить
   картинку, увидеть браузер сессии. Первое и третье в CLI решаются, второе не
   проверено. Поэтому целевой контур — **CLI-сессии в tmux**, а Desktop
   остаётся для того, чего в вебе ещё нет.
3. **Работа разбивается на пять непересекающихся эпиков** (ниже). Порядок:
   сначала довести рабочее место, потом управление сессиями, потом узел
   фабрики, браузер — последним.

## 2. Вопросы, которые мы задали, и чем они кончились

**Закрыты фактом** (проверено, не рассуждением):

| Вопрос | Ответ |
|---|---|
| Можно ли нажать форму вопроса (HITL) снаружи? | В Desktop — нет. **В CLI — да**: цифры отмечают, `Tab` между вопросами, `Enter` на Submit. Проверено на форме из двух вопросов |
| Как считать остаток подписки для раскладки волн? | `/usage` снимается через tmux; лимит **общий на аккаунт**, параллелить внутри одного бессмысленно |
| Логинится ли Claude внутри контейнера? | Да: `claude setup-token` печатает ссылку, дальше вход в браузере. Собран образ Debian + Claude Code 2.1.227 |
| Есть ли в Refero свежий интерфейс Claude? | Нет: только страницы входа и маркетинг. Эталон — скриншот CTO |
| Где живёт заданный вопрос? | В будке проекта (`.nyron-hub/hub.db`), не в чате волны |

**Решены как замысел** (спорили и договорились):

| Вопрос | Решение |
|---|---|
| Подписки — это изолированные мирки? | Нет. **Пул слотов**: файлы проекта одни, изоляция волн — рабочими деревьями git, подписка выдаётся как мощность |
| Что делать с Desktop при переходе на CLI? | Оставить. Он закрывает вложения и встроенный браузер, пока их нет в вебе |
| Ссылки на трекер — куда открывать? | Тикеты попапом (человек там залогинен), прочее — вкладкой |
| Как группировать сессии? | Как устроена работа: **эпик → диспетчер → волны**, плюс «вне эпика» |

**Открыты — нужен ответ или проверка:**

| Вопрос | Кому | Почему важно |
|---|---|---|
| Работают ли картинки в CLI? | проверить (проба была на негодной фикстуре) | единственная причина держаться за Desktop, кроме браузера |

| Смотреть браузер сессии или ещё и вмешиваться? | **решение CTO** | определяет выбор: лёгкий стрим кадров или тяжёлый noVNC |

## 3. Эпики (непересекающиеся, покрывают всё)

### Э1. Рабочее место в браузере доведено до эталона
**Зачем:** сегодня морда показывает разговор, но не показывает работу — чем
сессия занята, какие у неё файлы, что она наменяла.
**Состав:**
- панель фоновых задач и субагентов (таймеры, разворачивание);
- вкладка файлов с фильтром и поиском по содержимому;
- коммит-бар: репозиторий, ветка, размер изменений;
- статус ввода: модель, режим прав;
- общий список вопросов по всем проектам (сейчас только по одному);
- карта работы: эпик → диспетчер → волны вместо плоского списка.
**Готово, когда:** рабочий день CTO проходит во вкладке без переключения в
Desktop ради «посмотреть, что там».
**Зависит от:** ничего, можно делать сразу.

### Э2. Управление сессиями из браузера (контур CLI)
**Зачем:** снять потолок Desktop — отвечать на формы, вести сессию, поднимать
новые волны, не трогая приложение.
**Состав:**
- нажатие HITL-формы из браузера (механика снята, дело за кодом);
- терминал сессии в браузере;
- запуск новой сессии из STOVP (замена `/goal`-чипов);
- вложения: файл в рабочую папку и в чат;
- проверка картинок в CLI и решение по итогу.
**Готово, когда:** сессия ведётся из браузера целиком, включая ответ на форму.
**Зависит от:** Э1 в части компоновки (куда всё это класть).

### Э3. Узел фабрики: контейнер, слоты, паспорт
**Зачем:** перенести флот с Мака на сервер без ручной сборки окружения.
**Состав:**
- образ узла (Claude Code, Codex, tmux, git);
- паспорт узла: какие секреты нужны и где лежат;
- панель готовности: «Jira ✓, Git ✓, подписка ✗ — вот строка для входа»;
- слоты подписок и распорядитель, кладущий волну туда, где есть лимит;
- общее файловое хранилище: что общее, что личное у слота.
**Готово, когда:** новый узел поднимается одной командой и берёт работу.
**Зависит от:** Э2 (в контейнере живут именно CLI-сессии).

### Э4. Браузер сессии
**Зачем:** видеть, что смотрит агент, и уметь вмешаться руками (логин, капча).
**Состав:** лёгкий стрим кадров либо полноценное окно через noVNC; общий
залогиненный профиль; изоляция и параллельность.
**Готово, когда:** из вкладки видно и при желании управляемо окно агента.
**Зависит от:** Э3 (живёт в контейнере).

### Э5. Доступ и гигиена (сквозной)
**Зачем:** как только рабочее место выходит за localhost, оно становится
ключом ко всему.
**Состав:** вход в морду; защита веток плагина от затирания; журнал находок;
правило «пушить в оригинал, а не в зеркало» (уже записано после инцидента).
**Готово, когда:** морду можно открыть снаружи и это не страшно.
**Зависит от:** делается параллельно, но **до** выхода наружу.

## 4. Порядок работ

```
Э1 рабочее место ──► Э2 управление ──► Э3 узел ──► Э4 браузер
                Э5 доступ и гигиена — параллельно, до выхода наружу
```

**Первым куском** берём Э1: панель задач и субагентов. Причина — она отвечает
на вопрос «что сейчас происходит», который CTO задаёт чаще всего, и не зависит
ни от чего другого.
