# План релиза stovp 0.1 — канон (плагин без пульта)

Дата: 07.09.2026. Статус: к исполнению в отдельной сессии. Решения CTO
зафиксированы в `docs/specs/2026-09-07-vibe-first.md` (модель) и
`docs/reviews/2026-09-07-plugin-audit.md` (вердикты по каждому куску).
Здесь — только порядок работ и приёмка. Кода в пульте (`morda/`) этот
релиз не трогает; `nyron-dev/` не правится ничем, кроме версии в
`marketplace.json`.

**Репозиторий (решение CTO 07.09): новый `lanmiller/stovp` на GitHub,
приватный, GitHub — канон (без GitLab-зеркала).** Туда едет всё STOVP:
плагин `stovp/` сейчас, пульт `morda/` — релизом 0.2 (у него живой
launchd-путь на Маке, переезд — отдельный шаг). Раскладка:

```
stovp/                      ← репо
  .claude-plugin/marketplace.json   (плагин ./stovp)
  stovp/                    ← плагин (копия nyron-dev с правками по шагам)
  docs/                     ← спека, разбор, план, хендофф (копия из
                               nyron-dev-plugin/docs на 07.09)
  morda/                    ← с 0.2
```

Заведение репо — руками CTO (у GitHub-интеграции сессий нет права
создавать репозитории): GitHub → New repository → `stovp`, Private, без
README. Затем в новой сессии: `add_repo lanmiller/stovp` с push,
`git clone`, seed по шагу 1.

## Правила стройки

- Работать в `lanmiller/stovp`, ветка от `main`; коммиты мелкие, заголовок
  `stovp: <что>`; пуш в `origin` (GitHub — канон этого репо).
  `nyron-dev-plugin` остаётся на GitLab-каноне и не трогается.
- Каждый шаг — проверка фактом (команда в колонке «приёмка»), не «сделано».
- Ничего не удалять из `nyron-dev/`: у команды он стоит и работает.
  Архив — `docs/archive/nyron-dev/` (копия того, что не переезжает).
- Астра-ревью на финале по `cross-review.sh -C . -b main -s L -e auto`.
