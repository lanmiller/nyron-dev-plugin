## Рефакторинг-контур (функция 9, развёрнуто)

Проблема: ~100 задач рефакторинга; легаси написано разными моделями в разные
эпохи — «чёрт ногу сломит»; руками это не разгрести, а бросить нельзя
(ровный код = скорость всех будущих волн).

Принцип безопасности (из dev-best-practices, кейс «эталонного верификатора»):
**арбитр рефакторинга — существующие тесты и UJM, не мнение модели.**
Рефакторинг = «поведение не изменилось»: сьют и затронутые UJM зелёные до и
после. Где проверки нет — рефакторить запрещено, сначала появляется проверка.

Конвейер (все шаги — job'ы, человек только на вердиктах):

1. **Инвентаризация — не руками.** Фоновые сканеры пополняют живой реестр
   долга: мёртвый код (knip/vulture), дубли механизмов (граф
   codebase-memory), файлы-переростки (CODE_SIZE_GUIDELINES), устаревшие
   паттерны от старых моделей. Существующий список 100 задач загружается
   в реестр как затравка — и проходит дедуп против сканеров.
2. **Скоринг: рефакторим там, где ходим.** Приоритет = горячесть файла
   (частота правок волнами по git-истории) × размер долга. Холодное легаси,
   куда никто не лезет, лежит в хвосте — трогать его дороже, чем терпеть.
3. **Гейт покрытия.** Job разрешён только там, где участок накрыт тестами
   или UJM. Нет покрытия → сначала job «характеризационные тесты»
   (зафиксировать ТЕКУЩЕЕ поведение как есть, даже кривое) — и только
   потом рефакторинг.
4. **Исполнение атомарно.** Один механизм = один job = один маленький MR
   (дешёвая модель — GLM/Sonnet; лестница и quality_floor охраняют от
   «улучшайзинга»: цель — меньше сущностей, не «красивее»). Легаси-политика
   плагина действует: дубль → снос по правилу трёх исходов.
5. **Верификация.** Полный сьют + затронутые UJM + кросс-ревью другой
   семьёй; дифф-гейт «тестовые файлы не изменились» (кроме шага 3).
6. **Фоновый режим с капом.** Как ночная регрессия: простаивает квота →
   конвейер берёт следующий пункт реестра. Кап N MR/день — чтобы ревью и
   очередь мержа не захлебнулись. Реестр на вышке: сколько долга, скорость
   сгорания.

Итог: 100 задач превращаются из мёртвого списка в самопополняющийся реестр,
который фабрика сжигает фоном на дешёвых токенах, с математической страховкой
«поведение не изменилось».

## Что осознанно НЕ строим

- Замену Jira/будки новой шиной — дорабатываем существующие.
- GUI-автоматизацию Desktop-окон (мышкой по скриншотам) — окна для человека.
- Свой дашборд метрик с нуля — сенсоры готовые (OTel/ccusage), своя только
  доска волн над нашей же SQLite.
- Свой merge-механизм — GitLab merge trains.
- Форк Claudexor сейчас — зависимость + PR-политика; форк по триггеру
  (проект умер / PR-путь заглох).
