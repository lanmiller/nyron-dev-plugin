# Карта системы STOVP: что есть → что будет

Пара к [VISION.md](VISION.md): VISION — зачем, принципы и обоснования;
карта — инвентарь по функциям. Обновлено: 2026-07-28.

Колонка «Этап» — по дорожной карте VISION: 0 гигиена → (1 сигнал ‖ 2
UJM+каноны) → 3 демон → 4а/4б флот → 5 петля. Этапы 1–2 строятся волнами
плагина; этап 0 — синхронными сессиями.

Функции сгруппированы MECE: **производство** (1–10) — как работа проходит
от идеи до продакшена; **платформа** (11–14, 18, 21–25) — на чём это
работает; **знания и люди** (12, 15–17, 19–20) — что направляет и кто
пользуется.

Проблема: ~100 задач; легаси от разных моделей; руками не разгрести,
бросить нельзя (ровный код = скорость всех будущих волн).

Принцип безопасности: **арбитр — существующие тесты и UJM, не мнение
модели**. Рефакторинг = «поведение не изменилось»: сьют и затронутые UJM
зелёные до и после. Нет проверки — рефакторить запрещено, сначала
появляется проверка.

Конвейер (шаги — job'ы, человек — на вердиктах):

1. **Инвентаризация не руками**: сканеры (мёртвый код, дубли по графу,
   файлы-переростки, аудит переусложнения по паттерну ponytail-audit,
   жатва маркер-комментов осознанных упрощений) ведут живой реестр;
   100 задач — затравка с дедупом. **Реестр (решение 03.08)**: живёт в
   vault docs-репо — краткая запись (что, где, насколько больно) + линк
   на Jira-тикет, если заведён; вид «что делать?» — доска, отсортированная
   по серьёзности × горячести, мозолит глаза разработчику при старте
   работы; периодический аудит актуальности — пункт, не подтверждённый
   сканером, закрывается, реестр не гниёт.
2. **Скоринг «рефакторим там, где ходим»**: горячесть файла по git-истории
   × размер долга; холодное легаси — в хвост.
3. **Гейт покрытия**: нет тестов/UJM на участке → сначала job
   «характеризационные тесты» (зафиксировать текущее поведение как есть).
4. **Атомарно**: один механизм = один job = один маленький MR (дешёвая
   модель; quality_floor охраняет от «улучшайзинга»). Широкие механические
   рефакторинги (переименование через всю базу) — не одним махом, а
   схемой «расширить → мигрировать пачками → удалить старое»
   (expand–contract, паттерн из скиллов Покока): новая форма добавляется
   рядом со старой, вызовы переезжают порциями при зелёном CI, старая
   форма удаляется последним шагом.
5. **Верификация**: полный сьют + затронутые UJM + кросс-ревью другой
   семьёй; дифф-гейт на тестовые файлы.
6. **Фон с капом**: простаивает квота → следующий пункт реестра; кап N
   MR/день; реестр и скорость сгорания — на вышке.

## Что осознанно НЕ строим

- Замену Jira/будки новой шиной — дорабатываем существующие.
- GUI-автоматизацию Desktop-окон — окна для человека.
- Свой стек метрик — сенсоры готовые (OTel/ccusage).
- Свой мерж-механизм — GitLab merge trains.
- Форк Claudexor без триггера — зависимость + PR-политика.
